# P1.3 — Content and Domain Foundation

Status: **DONE**

**Read with:** [`P1.1-technical-foundation.md`](P1.1-technical-foundation.md) when changing boundaries or persistence contracts.

## Contract

- Professions, items, equipment slots, actions, recipes, loot tables, modifiers, dungeons, and entitlements use validated stable IDs and data-defined registries.
- Registry construction rejects malformed or duplicate definitions, invalid numbers, missing references, incompatible tags, duplicate list entries, and dependency cycles.
- Definitions are copied and frozen; iteration and modifier application are deterministic.
- Player data is versioned and Roblox-serializable. Runtime transactions replace affected mutable branches and return explicit results/errors.
- New content should normally require configuration and assets, not a new save, inventory, offline, or UI framework.

Representative content exists only to prove these contracts and is not a commitment to the public item catalog.
