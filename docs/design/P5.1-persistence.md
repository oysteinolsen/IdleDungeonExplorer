# P5.1 — Persistence

Status: **PLANNED**

**Read with:** [`P1.1-technical-foundation.md`](P1.1-technical-foundation.md) and the brief for every persisted active action.

- Persist a versioned envelope containing stable-ID player data and the active action snapshot needed to resume or simulate elapsed time.
- DataStore failures are explicit network failures: bound retries, surface errors, and never silently discard player data.
- Loading distinguishes current, migratable, future, and invalid schema versions. Migrations are ordered, versioned, tested, and never erase unknown/future data by pretending it is current.
- Cumulative XP and its curve version are authoritative. Raising a content cap is not a curve migration; changing a published curve is.
- Removed/renamed content or equipment slots requires explicit recovery behavior, normally returning affected items to the bank or a bounded recovery container.
- Provide Studio-safe persistence adapters so tests never depend on production DataStores.
- Server transactions and save retries must be idempotent where replay is possible, especially purchases, Forging reservations, loot banking, and death loss.
